# 银河终端商业版设计规格

## 1. 文档状态

- 状态：已批准
- 日期：2026-07-30
- 产品定位：面向开发者和多 Agent 工作流的商业级多终端管理软件
- 首发平台：Windows 10/11
- 平台策略：Windows 优先，PTY、通知、菜单和安装能力通过平台适配接口为 macOS/Linux 预留边界
- 技术路线：Tauri 2 + Rust + React + TypeScript + xterm.js WebGL

本规格补充并约束仓库根目录的 `设计文档.md`。原文列出的功能均属于最终商业版范围；里程碑只规定实现顺序，不缩减最终验收范围。

## 2. 产品目标

银河终端将项目、终端会话、分屏、命令块、Git 和主流编码 Agent 历史集中在一个高性能桌面工作区中。用户能够在多个项目与会话之间快速切换，辨认正在工作的 Agent，恢复历史会话，并在应用重启后恢复布局与工作上下文。

成功标准：

1. 高频终端输出期间，键盘输入、标签切换和其他 pane 保持响应。
2. 项目、会话、分屏比例、窗口状态和设置在异常退出后可安全恢复。
3. Claude Code、Codex CLI、OpenCode、OMP、Grok Build 和 Crush 的历史均可按项目发现并恢复。
4. 文档中的快捷键、搜索、Workflow、触发器、Git、通知、诊断和 Windows 系统集成全部可用。
5. 安装、升级、卸载、签名、许可清单、隐私与诊断能力满足商业发布要求。

## 3. 技术架构

### 3.1 进程与模块

- `src-tauri/core`：项目、会话、pane、布局、设置、Workflow、触发器和通知的领域模型。
- `src-tauri/pty`：统一 `PtyBackend` 接口；Windows 实现使用 ConPTY，后续平台可替换为 Unix PTY。
- `src-tauri/services`：Agent 历史扫描、Git、Shell 探测、持久化、命令块索引和诊断。
- `src-tauri/platform`：单例、窗口、系统通知、右键菜单、协议激活和安装相关的平台适配。
- `src-tauri/commands`：白名单 Tauri command 和事件协议；不向 WebView 暴露通用文件或进程执行能力。
- `src/features`：React 功能模块，按 projects、sessions、terminal、agents、git、search、settings 分区。
- `src/shared`：类型化 IPC 客户端、设计令牌、通用组件和国际化资源。

Rust 后端是持久状态的唯一权威来源。React 使用 Zustand 保存选择、面板开关、临时表单等短生命周期 UI 状态，不复制业务真相。

### 3.2 终端数据通路

每个 pane 对应一个独立 PTY 和 xterm 实例。PTY 输出在 Rust 端按 pane 收集，在同一调度窗口内合并为有序批次后发送到 WebView。键盘输入、调整尺寸和中断信号直接发送，不参与批处理。

输出事件包含 pane ID、递增序号和数据。前端发现序号缺口时请求后端环形缓冲重放；缓冲已淘汰时显示明确的截断标记。单 pane 设独立缓冲与配额，避免高吞吐任务阻塞其他 pane。

xterm.js 默认加载 WebGL addon；初始化失败或上下文丢失时释放 addon 并回退到内置渲染器，不中断 PTY。终端正文使用 Cascadia Mono、Microsoft YaHei UI 等宽回退组合。

### 3.3 安全边界

- Tauri capability 仅授予明确窗口和 command 所需权限。
- Agent 文件与 SQLite 数据库只读打开。
- Git 使用参数数组启动，不拼接交互 shell 字符串。
- Workflow 模板参数先按声明类型校验，再作为 PTY 输入或进程参数传递。
- 外部链接、文件打开和路径访问均进行协议、规范化路径和允许范围校验。
- 日志默认脱敏用户路径、命令参数和终端内容；诊断包由用户主动生成并展示包含范围。

## 4. 领域模型

### 4.1 实体

- `Project`：ID、名称、规范化路径、颜色、默认 Shell Profile、创建时间、最后访问时间。
- `Session`：ID、项目 ID、标题、排序、Agent 类型、布局树、同步输入状态、恢复元数据。
- `LayoutNode`：`Split` 或 `Pane`；Split 含方向、权重和两个子节点。
- `Pane`：ID、工作目录、Shell Profile、PTY 尺寸、动态标题、活动状态、退出码。
- `ShellProfile`：ID、名称、程序路径、参数、图标、环境变量和来源。
- `CommandBlock`：ID、项目/会话/pane、命令、输出、时间、退出状态和收藏状态。
- `AgentConversation`：Agent 类型、外部 ID、项目路径、摘要、消息时间、状态和恢复命令。
- `Workflow`：命令模板、参数定义、默认目录、Profile 和确认策略。
- `Trigger`：正则、作用域、冷却时间及通知、标记、响铃、停止滚动动作。
- `AppConfig`：schema 版本、语言、字号、主题、快捷键、状态栏、通知、窗口状态和功能开关。

### 4.2 不变量

- 每个 Session 必须属于一个现存 Project。
- 每棵布局树至少含一个 Pane，且所有分割权重规范化为有效比例。
- Pane 只能被一个 Session 的布局树引用。
- 跨标签移动 Pane 是事务操作；目标接纳失败时保留源 Pane。
- 删除项目不会删除磁盘目录；仍在运行的会话必须先获得用户确认。
- Agent 恢复命令只由已识别的适配器生成，不执行历史文件中的任意命令字段。

## 5. 功能设计

### 5.1 项目、会话与标签

项目决定侧栏、Git、新建终端和 Agent 历史的上下文。全局标签可同时展示多个项目中的 Session；切换标签同步当前项目。标签支持重命名、关闭、关闭其他、横向滚动、拖拽排序和 `Ctrl+W`。

OSC 0 标题经 basename 简化后更新标签；空标题回退为“终端 N”。标签和项目侧栏显示 Agent 徽章，正在输出的终端显示低频活动脉冲。

应用重启时重建布局和 PTY。普通会话恢复 Shell 与工作目录；带已验证 Agent 恢复元数据的 pane 在 PTY 就绪后注入对应 resume 命令。单个 pane 恢复失败不阻止其他会话。

### 5.2 分屏与布局

递归 `LayoutTree` 支持向右和向下分屏。拖动分隔条只更新权重，不重建终端。支持方向键切 pane、带 Shift 调整尺寸、关闭 pane、同步输入和将 pane 移到其他 Session。

持久化时 `layoutSnapshot` 优先于命名模板。设置中心可保存、覆盖、删除和应用布局模板。应用模板时明确选择复用现有 pane 或创建新 pane，默认复用并为缺口创建新 pane。

### 5.3 命令块与搜索

命令块优先使用 Shell Integration 标记建立可靠边界；不支持集成的 Shell 使用输入提交和提示符启发式，解析失败时退化为普通终端，不误阻断输出。命令块支持复制命令、复制输出、重跑和收藏。

- `Ctrl+F`：当前 Session 所有 pane 的 xterm 查找。
- `Ctrl+Shift+F`：持久命令块搜索。
- `Ctrl+R`：历史命令与收藏的统一搜索。
- `Ctrl+P`：全局命令面板。

`blocks.jsonl` 最多保留 500 个非收藏块；收藏块不因容量淘汰，超出软限制时提示用户清理。

### 5.4 Agent

六个 Agent 适配器实现统一接口：扫描、项目匹配、元数据解析、消息读取、状态推断和恢复命令生成。

- Claude Code：`~/.claude/projects/<sanitized-cwd>/<uuid>.jsonl`
- Codex CLI：`~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`
- OpenCode：`~/.local/share/opencode/opencode.db`
- OMP：`~/.omp/agent/sessions/<sanitized-cwd>/<timestamp>_<uuid>.jsonl`
- Grok Build：`~/.grok/sessions/<url-encoded-cwd>/<uuid>/`
- Crush：`<project>/.crush/crush.db`

扫描采用增量索引、文件时间戳和取消令牌。格式变化、数据库锁或缺少运行时只会使对应适配器进入“不可用”状态。状态解析输出尾部为 `idle`、`working` 或 `blocked`；PTY 退出为 `done`。从 working 转为 idle/done 或 blocked 时，按设置发送系统通知并写入通知中心。

### 5.5 Git

Git 服务提供分支、ahead/behind、变更计数和文件列表。状态栏分支菜单支持 checkout；工作区有未提交改动且切换可能冲突时显示 Git 返回的具体错误，不自动 stash 或丢弃修改。

仓库状态按项目缓存并在文件变化、终端焦点恢复和用户刷新时更新。Git 不可用或项目非仓库时，面板呈现可操作的空状态。

### 5.6 设置、Workflow、触发器与诊断

设置中心包含通用、Workflows、布局模板、触发器和快捷键。通用设置覆盖终端/UI 字号、中英文、默认 Profile、全局热键、右键菜单、Agent 通知及状态栏组件顺序。

Workflow 使用 `{{param}}` 参数，运行前展示已解析命令和目标目录。触发器正则限制长度，并使用有执行时间保护的引擎；动作支持通知、标记、响铃和停止滚动。

快捷键可查看、修改、禁用和重置。冲突在保存前阻止并指出冲突命令。诊断页展示版本、OS、Shell、配置路径、PTY 后端和功能开关，可生成脱敏报告。

### 5.7 Windows 集成

- 强制深色并使用自定义可拖拽标题栏及原生窗口按钮。
- 单例运行；二次启动聚焦现有窗口并转发 `--open-here`。
- 记忆窗口位置、尺寸和最大化状态，并在显示器变化后校正到可见区域。
- 注册资源管理器目录、目录背景和驱动器的“在此处打开星轨终端”。
- 自动探测 Windows PowerShell、pwsh、cmd、Git Bash 和 WSL，并允许自定义 Profile。
- 默认启用硬件加速；`CAPTURE_SCREEN` 模式切换到软件渲染以保证自动截图稳定。

## 6. 界面设计

主窗口由自定义标题栏、全局标签栏、项目侧栏、终端工作区、右侧多功能面板和状态栏组成。右侧面板在 Agent、Git、历史和通知间切换，不使用嵌套卡片。

视觉主题采用银河像素风，但终端区域保持克制：深空蓝黑背景、星云紫主强调、青色运行态、琥珀阻塞态和红色错误态。星点只用于非终端空白区域；Agent 徽章可有像素化轮廓和低频辉光。所有动画遵循系统减少动态效果设置。

所有核心操作支持键盘；状态不只依赖颜色表达。文本、焦点环和控件对比度达到 WCAG AA。固定工具栏、标签、pane 和状态栏使用稳定尺寸，动态状态不得引发布局跳动。

## 7. 持久化与迁移

- `store.json`：项目、会话、布局、设置和窗口状态。
- `blocks.jsonl`：命令块记录。
- `backups/`：最近一次有效主存储备份。
- `logs/`：滚动、脱敏的应用日志。

所有结构含 schema 版本。主存储写入流程为序列化到同目录临时文件、刷新、替换原文件并保留最后有效备份。启动时依次尝试主文件、备份和安全默认值；不会覆盖损坏文件。迁移按版本逐步执行并有样本测试。

## 8. 错误处理与可观测性

错误分为可恢复功能错误、会话错误和应用级错误。Agent、Git 或单个 PTY 失败只影响对应模块；持久化不可写会进入只读警告状态；无法初始化核心存储才阻止进入主界面。

用户消息包含发生事项、影响范围和下一步操作，不展示 Rust 堆栈。日志使用结构化事件、关联 ID 和模块级别。崩溃重启后提供恢复上次工作区或清洁启动，且保留原始恢复数据。

## 9. 测试与发布门槛

### 9.1 自动化测试

- Rust 单元测试：布局树、不变量、迁移、Shell 探测、六类 Agent 解析、命令块和触发器。
- TypeScript 单元测试：UI 状态、快捷键、标签、面板和格式化逻辑。
- 契约测试：所有 Tauri command、event、DTO 和错误码。
- 集成测试：真实 ConPTY、PowerShell、cmd、Git Bash、WSL、Git 仓库和 Agent 脱敏样本。
- Playwright E2E：项目、标签、分屏、比例、跨标签移动、同步输入、搜索、设置、恢复和错误状态。
- 视觉回归：桌面及最小支持窗口尺寸、100%/150%/200% 缩放、中文/英文和截图模式。

### 9.2 性能与稳定性

- 高频输出期间键盘回显和其他 pane 交互保持可用，不发生 UI 线程长时间阻塞。
- WebGL 初始化失败和上下文丢失均能自动降级。
- 至少覆盖多项目、多 Session、多 pane 的持续运行与重复恢复测试。
- Agent 大型历史目录采用增量扫描，不在 UI 线程执行文件遍历或 SQLite 查询。
- 性能基准记录输出吞吐、批次数、输入延迟、内存和启动/恢复时间，用发布基线检测回归。

### 9.3 商业发布

- 在干净 Windows 10/11 虚拟机验证安装、升级、卸载、右键菜单、单例和 `--open-here`。
- 生成 NSIS 安装包；代码签名证书通过 CI 密钥提供，不提交仓库。
- 自动更新使用签名清单，并支持稳定/预览通道和失败回滚。
- 发布物包含第三方许可清单、隐私说明、变更记录、诊断说明和可复现构建步骤。

## 10. 实施里程碑

1. 基础平台：Tauri 工程、领域模型、持久化、设计系统、窗口与测试基础设施。
2. 终端工作区：ConPTY、xterm WebGL、标签、项目、分屏、布局恢复、Shell Profiles。
3. 生产力功能：命令块、三类搜索、命令面板、Workflow、触发器、快捷键和状态栏。
4. Agent 与 Git：六个 Agent 适配器、历史面板、恢复、状态、通知和 Git 面板。
5. Windows 集成：单例、窗口记忆、系统通知、右键菜单、`--open-here` 和诊断。
6. 商业发布：性能治理、完整自动化、可访问性、安装更新、签名、许可与发布文档。

每个里程碑必须保持可运行并通过其新增测试。只有全部里程碑以及根设计文档的逐项验收通过，才视为产品完成。

## 11. 非目标与明确约束

- 首版不提供云同步、账户系统、远程终端或团队协作服务。
- 不修改或删除 Agent 自有历史数据。
- 不实现自有 Shell 或终端转义序列解析器，终端仿真由 xterm.js 提供。
- 不自动执行破坏性 Git 恢复、stash、reset 或 clean 操作。
- macOS/Linux 不属于首发交付物，但核心接口不得硬编码 Windows 路径与行为。
